# SLA / SLO 定义

> 内部实验口径：目标是 SLO，作为可测量目标；对外承诺的 SLA 是后期业务问题。

## 1. SLO 总表

| 指标 | 正常态目标 | 故障态目标 | 统计窗口 | 备注 |
|---|---|---:|---|---|
| 可用性 | ≥ 99.95% | 单点故障下持续可服务，不中断 | 月度 | 正常态按请求数折算 |
| 查询 P99 | ≤ 200ms | ≤ 500ms（降级态） | 每次压测窗口 | 商品/库存查询 |
| 下单 P99 | ≤ 500ms | ≤ 1s（有界降级） | 每次压测窗口 | 不含客户端超时重试 |
| 系统错误率 | ≤ 0.1% | 不做错误预算保证，但要可观测 | 每次压测窗口 | 库存不足、限流不算系统错误 |
| 后置任务完成 P99 | ≤ 5s | 突发态另设积压年龄 SLO | 每次压测窗口 | EXP-09 后启用 |

## 2. 错误分类

| 类别 | 计入系统错误率 | 说明 |
|---|---|---|
| 成功（2xx，业务成功） | 否 | 幂等重放返回原结果也算成功 |
| 库存不足拒绝 | 否 | 业务结果，不按系统错误算 |
| 限流拒绝（429） | 否 | 保护性拒绝，单独统计 |
| 服务端 5xx / 超时 | 是 | 计入错误预算 |
| 幂等冲突 | 否 | 客户端参数错误，不计入 |

## 3. 统计口径

- **可用性分母**：全部到达请求（含限流拒绝、库存拒绝），不通过排除非 2xx 来美化指标。
- **错误预算**：99.95% 可用 ≈ 每月约 21.6 分钟故障窗口，用于判断是否需要停止新功能修复稳定性。
- **长稳要求**：毕业前至少一次 2 小时连续压测，期间错误率、P99 不得随时间持续劣化。
- **不做**：只看平均延迟（必须 P95/P99）、只看应用不看 DB/Redis/Kafka、只测成功路径。

## 4. 故障态定义

| 故障 | 期望表现 | 允许影响 |
|---|---|---|
| Pod kill | 自动恢复，请求不丢失 | 短暂 5xx，恢复后重试成功 |
| Node down | 服务继续（多副本） | 副本分散后剩余容量需满足 |
| Redis down | 回源 MySQL 或降级 | 查询延迟上升，下单不受影响 |
| MySQL Primary down | 自动 failover | EXP-16 后按 RTO 目标验收 |
| Kafka broker down | 消息不丢，恢复后重放 | 后置任务延迟上升 |
